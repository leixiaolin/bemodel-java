## 1. 背景、目标与边界

### 1.1 当前实现

接口链路为 `POST /api/cs/ask` → `CsService.ask` → `SemanticQaService.answer`。依据当前源码：

- `cs/semantic.py` 的语义上下文包含已发布概念、属性、confirmed 物理映射和概念关系，尚未纳入规则、动作、公理。
- ANALYTICS 场景的口径类问题可由 `CsService.ask` 提前返回指标卡；指标库当前不直接参与统计查询执行。
- MODEL_ANSWER 依赖规划结论和可选验证 SQL，缺少规则、动作、公理的结构化引用。这是潜在的无依据结论来源，影响大小需评测确认。
- `CsService.ask` 在语义服务前还有 LLM/关键词路由。直接调用 `SemanticQaService.answer` 不能代替完整入口验收，也不能证明整条链路不调用 LLM。

### 1.2 目标与非目标

提高业务口径一致性，使用户能够查看回答所依据的资产；在严格适用范围内使用已核对的指标探针，减少规划调用。

本期不实现任意指标参数化、不自动将中文规则编译成确定性约束、不更换现有 SQL 校验器、不修复独立的 `MetricService.evaluate` 执行路径。不能将监控探针天然视为指标公式，也不能将编码存在性校验称为答案正确性证明。

### 1.3 实施约束

- 保持 `{code:0, msg:"ok", data:...}`、既有字段含义、camelCase 及实体空字段 `null` 约定；沿用 `core/result.py`，不改写 SQL 返回列名。
- 指标查询也必须经过现有白名单校验、15 秒执行超时、100 行读取上限；一般查询继续最多展示前 20 行。
- 不改 `cs/prompts.py` 的抽取常量，在 Python 专用模块追加补充指令；运行时不读取 Java 源码。
- V1–V28 等历史迁移不改。若后续修正指标资产，另加 Python 增量迁移并检查兼容性；本期通过资格清单限制直查，不修改已有监控口径。
- 保留工作区现有未提交改动。具体文件以实施前 `git status --short` 为准，不把本次工作区快照当作永久排除清单。
- 所有集成验证使用隔离数据库。真实 DeepSeek 与 StubLLM 的结果分别报告。

## 2. 资产事实与指标准入

### 2.1 规则、动作、公理

种子数据包含约 14 条规则、9 条公理、9 条动作；运行时数量和状态以实际数据库为准。三类均只使用 `status == 'PUBLISHED'` 的资产，不因 engine 为 QC 就排除。已发布只代表可纳入上下文，不代表内容必然正确或彼此一致。

动作的 `from_status`、`to_status` 多为业务状态描述；物理枚举码仍以目标数据源的 confirmed 映射为准。公理的因果、依赖关系不能替代 JOIN 键和基数证据。

### 2.2 现有探针与指标语义核对

依据 `db/migration/V3__seed_ontology.sql` 和 `V4__metric_monitor.sql`：

| 指标 | 当前探针实际含义 | 本期直查资格 |
|---|---|---|
| CANCEL_NOT_REFUND | 当前数据源中医嘱已取消、费用仍正常的费用明细笔数 | 首批候选；核对资产与映射后开放，无时间/科室/患者等附加条件 |
| DISCHARGE_COUNT | 全量已结算记录中的去重住院号数 | 不开放。定义要求统计周期，探针没有周期过滤；不得把“出院人数是多少”默认解释为全历史 |
| LAB_CANCEL_RATE | 状态 C/X 的撤销申请数量 | 不开放。定义/公式是比例，探针是监控绝对量，不能将数量作为撤销率返回 |
| AVG_INP_FEE | 全量已结算金额除以去重住院号数，并 ROUND 到整数 | 暂不开放。需明确统计范围、金额单位、精度和空分母规则后再准入 |

以上是种子源码的静态核对，不替代运行库验证。不得修改 V4 来消除不一致，也不得为问数悄悄改变现有监控行为。

### 2.3 首期资格清单

在 Python 专用 `cs/metric_policy.py` 中维护明确的直查资格记录，首期只纳入经测试核对的 CANCEL_NOT_REFUND。记录包括：

- 指标编码、允许的名称/别名、单位、统计范围、数值类型、精度及 NULL 策略。
- 经核对的 `definition`、`formula`、`ds_code`、`probe_sql` 内容指纹，以及相关枚举映射的预期含义。
- 人工核对依据、策略版本及对应测试用例。

运行时核对当前资产内容；任何相关内容变化、必填字段缺失或映射不一致都使资格失效，回落规划并记录原因。指纹采用固定编码和稳定摘要，不使用 Python 进程随机 hash。不以指标编码单独证明可信，也不把未核对的新指标自动加入直查。

该清单是首期明确的限制，不是第二套指标库；扩展到动态指标管理或参数化查询时另行设计审批、版本和生效机制。

## 3. 总体链路与配置

使用 `settings.semantic_asset_enhance` 控制资产注入、提示词补充、指标直查和引用验证四条增强线：

```python
semantic_asset_enhance: bool = Field(False, validation_alias="BEMODEL_SEMANTIC_ASSET_ENHANCE")
```

默认开启仍以第 8 节验收完成为前提；当前默认关闭，受控验证需显式设为 `1`。上线回退设置 `BEMODEL_SEMANTIC_ASSET_ENHANCE=0` 后重启；关闭时不执行资格检查、资产查询、引用处理或新增提示词，恢复原链路。

```text
CsService.ask：原有路由和口径卡
  → SemanticQaService.answer
    → 开启增强：严格指标准入与问题匹配
      → 合格：白名单校验 → 执行 → 结果形态校验 → 模板回答
      → 不合格/执行失败：原语义规划（附本次资产快照）
    → QUERY：校验/执行/必要的纠错 → 最终计划引用核验 → 回答
    → MODEL_ANSWER：引用核验 → 必要时重规划一次 → 回答或依据不足
```

`cs/services.py`、`cs/router.py` 原则上不改；保留既有路由语义。直查保证的是进入语义服务后跳过规划、纠错和作答 LLM，不保证此前 `CS_ROUTE` 不调用。完整入口路由未进入语义服务时，不强行声称指标直查已覆盖该问法。

## 4. 核心机制

### 4.1 资产上下文与本次快照

保留 `build_semantic_context(question=None)` 的字符串输出供已有调用使用；新增内部上下文构造器，返回文本及本次实际送入模型的结构化资产快照。规划、重规划和 critic 各自关联对应快照，不使用跨请求共享的“最后一次上下文”。

在既有概念、物理映射、关系后追加【业务规则】【概念公理】【状态动作】。每条包含类型、编码及必要业务字段；动作需包含前置状态、目标状态、trigger_desc 和 description，避免只看前置状态就推导无条件允许。

- 无合格条目时整段省略，含段头。
- 每类最多 30 条，按问题与条目文本的二字元组重合数降序、编码升序稳定排序。
- 新增资产文本总预算初始设为 12000 字符，单条最多 2000 字符；超限条目整体省略，不截断关键约束。记录省略数量，参数由评测调整。
- 同一资产的条件与例外必须成组提供。规则与动作冲突、必要依据被省略时，模型应说明依据不足，不自行选择有利条款。
- 不再声称固定增加约 1K token；报告实际字符数、模型可用的 token 统计和耗时。

资产内容作为数据区提供，补充指令放在其外；资产中的自由文本不具有覆盖 SQL 护栏和系统规则的权限。

### 4.2 指标匹配：完整问法覆盖，禁止模糊短路

`metric_direct_answer(q)` 在 `answer()` 的规划之前尝试，返回成功结果才短路。需同时满足：

1. 指标处于第 2.3 节资格清单且运行时核对通过。
2. 问题是取值请求，不是定义、公式、原因、明细或操作请求。
3. 用已批准别名和有限问句模板完整匹配问题，只归一化空白、标点及明确列出的礼貌词；匹配后不能残留未解释的业务内容。
4. 统计范围与资格记录一致，且唯一命中一个指标。

首期接受如“取消未退费笔数是多少”“取消未退费有多少笔”“现在取消未退费的费用有多少笔”；“现在/当前”只允许解释为此指标的当前数据快照，不代表当天发生量。

禁止使用 `name_match` 互含、LCS 或 `def_match` 单独触发执行。可用于后续候选检索，但不能作为直查资格。不能靠穷举时间词黑名单代替完整匹配。

| 问法 | 预期行为 |
|---|---|
| 取消未退费有多少笔 | 合格时直查；明确显示当前全量快照范围 |
| 今天取消未退费有多少笔 / 内科取消未退费笔数是多少 | 回落规划，保留时间/科室条件 |
| 按科室统计取消未退费笔数 / 取消未退费比昨天增加多少 | 回落规划，不支持分组/比较直查 |
| 取消未退费笔数和出院人数是多少 | 回落规划，不任选一个指标 |
| 出院人数是多少 / 今天出院人数是多少 | 不走探针直查；规划或明确统计周期缺口 |
| 检验撤销率现在多少 | 不走数量探针；正常规划比例计算或说明无法计算 |
| 取消未退费笔数怎么算 | 完整入口维持口径卡；语义服务直接调用时也不直查 |

### 4.3 指标执行、结果与失败边界

1. 从 `allowed(ds)` 取得 confirmed 映射白名单；为空则回落。
2. 使用现有枚举归一化和 `validate_sql`，执行前再次确认资格内容未发生不允许的变化。验证拒绝不得通过放宽白名单解决。
3. 复用 `execute` 的 15 秒超时和最多 100 行读取。直查不调用 `MetricService.evaluate`，也不写 `last_val/last_eval_at`，避免混淆监控巡检记录。
4. 仅接受**恰好一行、一列的有限数值**，不接受 bool、字符串、NaN/Infinity、多行或多列。COUNT=0 是合法值，不触发纠错。笔数必须为非负整数。
5. 空结果或 NULL 按资格记录处理；首期返回“暂无可用实测值”，不转成 0。形态错误或数值类型错误使直查失败，禁止取首行冒充整体指标。
6. 校验/执行/形态错误记结构化原因后回落原规划；直查失败本身不记概念缺口，后续原规划仍按既有规则决定是否记录 miss。日志不输出口令、连接串或敏感结果行。

成功结果采用确定性模板，无需调用 `CS_SEMANTIC_ANSWER`，防止重新表述时改变数值、单位或范围。例如：

> 当前全量数据快照中，取消未退费共 3 笔。口径：医嘱已取消但费用状态仍为正常的明细笔数。该结果不限定发生日期。

沿用 intent、evidence、links、rows 和语义解析字段结构；evidence 包含指标、指标口径、统计范围、单位、执行SQL、数据源、实测值。`执行SQL` label 保持不变。数值使用现有序列化约定，Decimal 不经过不必要的浮点转换；NULL 作为缺值展示。

告警只在有效数值及同单位阈值存在时按 `value > warn_threshold` 判断。`fill_parse` 的实际使用概念从 SQL 涉及表的 confirmed 映射提取，不能只填指标所属概念而遗漏关联表。

### 4.4 引用核验与依据不足

规划可提供 `axiomCodes`、`ruleCodes`、`actionCodes`。首先验证字段是有上限的字符串数组、去重，再核验：

- 编码与类型属于该次规划实际收到的资产快照；库中存在但被裁剪的资产不能引用。
- 当前资产仍为 PUBLISHED，且用于作答的关键内容与快照一致。内容变化或撤回时视为失效，不混用旧结论和新证据。
- 回答中展示的引用、证据正文、链接均由服务端从有效快照生成，不采信模型提供的资产名称、正文或 URL。

**编码有效性与结论支持度分开处理：**

- MODEL_ANSWER 出现无效引用时，最多重规划一次，明确指出失效项；不得仅删徽章后保留原结论。重规划使用新快照。
- 增强模式下 MODEL_ANSWER 必须有可核验依据。首期对没有有效业务资产引用的结构判断保守返回“当前已发布资产不足以确认”，不要求模型必须给“可以/不可以”。未来可另行扩展结构关系证据类型。
- 全部引用失效、重试失败、存在无法解释的冲突时，输出确定性的依据不足结果，保留已有有效证据但不输出肯定业务结论。不把有资产但证据不足一律记作概念缺失。
- QUERY 未声明引用时可按既有 SQL 结果回答；声明了失效引用则重规划一次，仍失败时返回依据不足，不继续执行以无效依据生成的计划。
- 纠错采纳新 SQL 后，原规划引用不能直接继承。首期清空该查询的规则/动作/公理引用，仅展示最终 SQL、结果和 corrections；后续若需保留，须核验最终查询与资产的关系。

有效资产正文加入作答 prompt，要求结论覆盖适用条件与例外。最终自由文本仍可能误解证据，因此只承诺确定性的引用来源校验；结论支持度通过标注评测和人工复核衡量，不宣称“强制一致”或正确率 100%。

### 4.5 提示词与 critic

在 Python 专用 `cs/asset_context.py` 定义补充指令，按开关追加到规划及作答流程。要点：

- 规则是业务条件依据，需区分正常状态、违例筛选和问题实际意图，不能把合规条件机械追加到所有 WHERE。
- 物理码来自目标数据源映射；动作描述不能覆盖映射。前置状态只是动作约束之一，空前置状态不等于无限制。
- 公理只提供语义约束，JOIN 必须有物理键证据。
- 只能引用本次快照编码；缺证据、冲突或范围不明时明确说明，不编造。

`agent_correct` 传入问题和资产上下文；保留现有纠错触发、修正 SQL 再校验及结果改善接受条件。新增资产不会自动证明 critic 的修正正确，需要专项用例验证。

## 5. 响应契约与前端深链

`citations` 是问答 data 中的可选新增字段，无有效引用时省略；引用项没有可用链接时 `route: null`，前端仅展示不可点击徽章。示例是完整 JSON 对象片段：

```json
{
  "citations": {
    "metric": {"code": "CANCEL_NOT_REFUND", "name": "取消未退费笔数", "route": "/glossary?metric=CANCEL_NOT_REFUND"},
    "rules": [{"code": "RULE-FEE-001", "name": "取消医嘱不得计费", "route": "/ontology?tab=rules&assetCode=RULE-FEE-001"}],
    "axioms": [{"code": "AX-005", "name": "医嘱→费用明细", "route": "/ontology?tab=axioms&assetCode=AX-005"}],
    "actions": [{"code": "ACT-ORDER-CANCEL", "name": "取消医嘱", "route": "/ontology?tab=actions&assetCode=ACT-ORDER-CANCEL"}]
  }
}
```

该示例用于展示字段结构，不要求每个回答包含所有类型。指标直查一般只有 metric。既有 evidence `{label,value}`、matchedConcepts、relations、corrections 和口径卡契约保持。

- `views/ask/index.vue` 保存并渲染当前消息的 citations，按类型展示徽章；只对合法内部 route 提供跳转。
- 指标页已有 `?metric=` 定位逻辑，复用其切页、清筛选和高亮行为。
- **新增**本体页协议 `?tab=rules|actions|axioms&assetCode=<编码>`。父页面切换标签并将目标编码传给对应面板；面板等待数据加载后定位、翻页、清除遮挡筛选、打开详情或高亮。
- 首次加载、同页更换编码、浏览器前进后退均应生效。不存在/已删除资产给出明确提示，不定位到任意其他记录。
- 原 `?concept=` 只打开概念详情，可作为相关概念链接保留，不能冒充规则/动作/公理的证据深链。

## 7. 实施顺序

1. 落实资格记录及固定数据用例，先证明允许直查的业务含义和匹配边界。
2. 完成资产快照、预算与引用校验，覆盖失效、冲突和重试上限。
3. 接入语义服务编排与响应；验证开关关闭恢复原行为。
4. 完成徽章和目标面板定位，验证引用到证据的完整路径。
5. 运行隔离集成测试、A/B 和回归，满足第 8 节门槛后交付。

## 8. 验证方案与验收门槛

### 8.1 单元测试（sqlite + StubLLM）

| 类别 | 必测行为 |
|---|---|
| 开关 | 关闭时四条增强线均不执行，不查询新增资产、不触发直查、不产生 citations |
| 资产选择 | PUBLISHED 过滤、空段省略、稳定排序、条目/总字符预算、被省略资产不可引用 |
| 指标准入 | 仅资格清单允许；定义、公式、SQL、数据源或相关枚举含义变化使资格失效 |
| 语义匹配 | 正向完整模板命中；时间、科室、患者、分组、同比、明细、解释、多指标、歧义均不直查 |
| 不一致探针 | 检验撤销率不执行撤销数量探针；出院人数不默认执行无周期探针 |
| 执行护栏 | 白名单拒绝、超时、执行失败回落；COUNT=0 不纠错；不更新监控最近值 |
| 结果类型 | 单值非负整数、Decimal、0、NULL、空集、多行、多列、非数值、非有限值各有明确结果 |
| 引用 | 有效、伪造、未发布、未送入上下文、内容变化、错误类型、超长列表与重复编码 |
| 依据不足 | 全失效/部分失效触发一次重规划；重试失败不保留原肯定结论；无引用不伪装成已验证 |
| QUERY/critic | 未声明引用的查询兼容；无效引用不直接执行；采纳纠错后清除旧资产引用，保留最终 SQL 证据 |
| 完整入口 | `CsService.ask` 的口径卡、关键词和 StubLLM 路由；不以服务层命中代替入口命中 |

### 8.2 MySQL 与接口验证

仅使用本机 **13317 / bemodel_py_test**，按 Python README 初始化并使用现有 fixture 保护。设置 `BEMODEL_MYSQL_TESTS=1`、`BEMODEL_DISABLE_SCHEDULER=1`、空 `DEEPSEEK_API_KEY`；禁止为适配其他数据库放宽校验。

固定数据同时包含取消且未退费、取消已退费、未取消、不同日期、不同科室的记录。独立计算预期笔数，不调用被测资格或匹配函数生成期望值；验证实际数值、单位、统计范围和执行 SQL，不只断言“含数字/含表名”。

比例反例数据至少含 2 条撤销、8 条未撤销，以区分数量 2 与比例 20%；即使本期该指标不直查，也必须验证不会将数量探针当成比例。NULL、多行和非法探针使用测试资产构造。

检查响应契约、VIEWER 查询访问、现有鉴权回归，以及失败后的数据库状态：不得更新指标监控值或业务库，概念缺口/LLM 日志遵循现有事务行为。

### 8.3 A/B 评测

脚本在连接前检查平台库和所有测试数据源均指向任务隔离环境；复用现有测试保护口径。两轮使用相同业务数据、冻结日期或明确记录基准日期；每问题独立会话，恢复开关用 `try/finally`。新增 miss/日志与业务结果分开统计，不把两轮日志混在一起。

**主报告所有问题通过 `CsService.ask(scene='ANALYTICS')` 执行**，另加少量 `/api/cs/ask` 契约验证及 CS 场景回归。直接调用语义服务只用于定位机制，不计入端到端成功率。StubLLM 套件与真实模型 A/B 分开；真实模型运行时仅在明确的评测进程配置 Key，不在测试代码、报告或日志保存秘密。

问题集至少覆盖：

- 合格指标的标准问法、批准别名、0 值与告警。
- 指标名称完全出现但附加时间/科室/患者条件、分组、比较、多指标及未知范围。
- 出院人数周期缺失、撤销率数量错配、均次费用精度和分母边界。
- 规则、动作、公理的有效依据、冲突、遗漏条件、全部伪造引用及被裁剪引用。
- 普通查询、口径卡、明确写操作请求和超出映射能力的问题。“导出药品价格表”等只读请求按实际映射能力标注，不能预设为拒答。

每题标注 `expectedValue`、`unit`、`scope`、必要筛选/分组语义、允许路径、预期引用与结论要点。口径卡等不适用数值断言的题目单独分类。

| 维度 | 判定方式 |
|---|---|
| 业务正确性 | 实际数值、单位、范围和必要条件与独立标注一致；关键词/表名只能辅助 |
| 引用有效性 | 类型、编码、已发布状态和本次快照一致；无引用样本单独统计，不计成 100% 命中 |
| 证据支持度 | 标注结论与条件/例外逐项核对；真实模型自由文本人工复核，不与编码有效率混为一谈 |
| 路径与调用 | 记录实际路由、直查、回落原因、按问题统计 LLM 调用；区分 CS_ROUTE、规划、作答及 critic |
| 性能 | 成功/失败分组统计耗时、prompt 大小、调用数和可用 token 数 |

确定性用例要求全部通过：误直查为 0、有效直查数值/单位/范围全部正确、无效引用不被展示、不受支持的肯定结论被规定的降级路径拦截。真实模型在同一问题集至少运行 3 轮，报告逐轮和分组结果；业务正确率、证据支持度不得低于基线，存在任何上述关键错误时不交付默认开启版本。

成本收益只比较实际进入合格直查的样本：语义服务内规划、作答、critic 调用应为 0，完整入口可能仍有 CS_ROUTE。未调用真实模型时仅报告确定性验证结果，不宣称成本或准确率提升已经成立。

报告按模式写入 `bemodel-server-py/artifacts/semantic-qa-eval-sqlite.json`、`semantic-qa-eval-mysql.json` 或 `semantic-qa-eval-real.json`，可用 `--output` 指定路径，避免不同验证覆盖证据。报告含代码内容摘要、数据夹具版本、策略版本、配置（脱敏）、运行时间、开/关逐题结果、预期值、失败原因及分组差异。SQLite 模式保存合成回答；真实环境不保存自由文本回答或敏感结果行。现有网关未向调用方暴露 token usage，报告据实使用 `null`，另报实际 prompt 字符数。

本地可执行 `python scripts/eval_semantic_qa.py --sqlite-fixture`；该模式不连接 MySQL，路由、规划、作答和 critic 全部使用 StubLLM，业务 SQL 在固定 SQLite 数据上实际执行。时间、科室、患者、分组和比例结果均有独立标注；冲突等场景验证服务对给定模型计划的处理，不能证明真实模型能识别所有冲突。真实环境的自由文本业务正确性和证据支持度仍须人工复核，报告的 `releaseGatePassed` 不因确定性断言通过而自动置真。

### 8.4 兼容性回归

- 开关关闭：完整 Python 回归，确认旧输出及异常/降级行为；双端 parity **无论有无 Key 均显式关闭增强**。
- 开关开启：运行新旧 Python 测试及业务断言。空资产不等于整条链路没有变化，不能提前宣称已有测试必然全绿。
- citations 是业务证据，不加入 VOLATILE。不通过忽略数值、状态、关联、引用等差异让报告变绿。
- 增强开启允许 Python 与 Java 出现设计明确的差异，单独列出并验收，不要求用归一化掩盖差异。
- 双端完整验收若执行，按 `ACCEPTANCE.md` 的 Java 18083→13319、Python 18084→13320 环境和初始化顺序操作，不在运行过写回放的库上直接重复。

## 9. 风险与交付表述

| 风险 | 控制与剩余限制 |
|---|---|
| 探针与公式不一致 | 首期资格清单与内容核对；未准入指标走规划，不能自动保证规划正确 |
| 误匹配忽略限制条件 | 完整问法覆盖、唯一命中及反例；牺牲部分召回率换取直查准确性 |
| 资产增长或冲突 | 条目/字符预算、请求内快照、冲突时依据不足；裁剪可能降低可回答率 |
| 有效引用但错误解释 | 不宣称确定性保证，通过条件/例外标注及真实模型复核评估 |
| 结果截断与精度 | 直查只接受严格单值，不取首行；资格记录明确类型、单位和缺值规则 |
| 无 Key 行为变化 | 合格指标可模板作答，其余保留既有降级；该变化单独验收 |
| 深链只到概念 | 新增资产级路由及面板定位，不用概念页跳转冒充引用证据 |

预期收益是合格指标减少模型规划和作答调用、业务资产可追溯、无依据结论更易被识别。准确率、证据支持度、延迟和成本均以本次评测为准，不预先承诺“SQL 错误率为 0”或“答案可核验性 100%”。
